ESPECIFICACIÓN LÉXICA (macros y tokens del TP REGEX)
=====================================================================
MACROS:
  LETRA             = [a-zA-Z]
  DIGITO            = [0-9]
  TERMINADOR_LINEA  = \r|\n|\r\n
  ESPACIO_BLANCO    = {TERMINADOR_LINEA} | [ \t]
  OPERADORES        = (\+|-|\/|\*|>|<|\!=|<=|>=|=)
  SIGNOS            = ,|:|;

TOKENS (cada uno con constante en la clase sym; usar EXACTAMENTE estos nombres):

Palabras reservadas:
  DECLARE            "DECLARE.SECTION"
  ENDDECLARE         "ENDDECLARE.SECTION"
  PROGRAM            "PROGRAM.SECTION"
  ENDPROGRAM         "ENDPROGRAM.SECTION"
  IF                 "IF"
  THEN               "THEN"
  ELSE               "ELSE"
  ENDIF              "ENDIF"
  WHILE              "WHILE"
  ENDWHILE           "ENDWHILE"
  WRITE              "WRITE"
  FLOAT_T            "FLOAT"
  INTEGER_T          "INTEGER"
  STRING_T           "STRING"
  AND                "AND"
  OR                 "OR"
  POSITION           "POSITION"
  Las reglas de palabras reservadas van ANTES que la regla de ID en el .flex.

Operadores:
  ASIGNACION         "::="
  ASIG_DECL          ":="
  OP_IGUAL           "=="
  OP_DISTINTO        "!="
  OP_MENOR_IGUAL     "<="
  OP_MAYOR_IGUAL     ">="
  OP_MENOR           "<"
  OP_MAYOR           ">"
  OP_SUMA            "+"
  OP_RESTA           "-"
  OP_MULT            "*"
  OP_DIV             "/"

Delimitadores:
  COMA               ","
  PUNTO              "."
  PUNTO_Y_COMA       ";"
  PAR_A              "("
  PAR_C              ")"
  COR_A              "["
  COR_C              "]"
  LLAV_A             "{"
  LLAV_C             "}"

Identificador:
  ID = {LETRA}(({LETRA}|{DIGITO}|\-)*({LETRA}|{DIGITO}))?
  ÚNICA modificación respecto del TP REGEX: el sufijo pasa a ser opcional para que un
  identificador de una sola letra (a, b, x) sea válido. La regex original exigía mínimo dos
  caracteres. El guion sigue permitido en el medio: "a-b" sin espacios es UN ID; la resta
  requiere espacios ("a - b"). Documentarlo en README y cubrirlo con un test.

Constantes:
  CTE_INT   = {DIGITO}{DIGITO}*
              Validar en la acción el rango entero 16 bits: 0..32767 (el signo es OP_RESTA, no forma
              parte del lexema). Fuera de rango -> error léxico.
  CTE_FLOAT = {DIGITO}+ "." {DIGITO}+ | {DIGITO}+ "." | "." {DIGITO}+
              Debe aceptar 99999.99, 99. y .9999
              Validar en la acción el rango float 32 bits: Float.parseFloat no debe dar infinito
              (máx 3.4028235e38). Fuera de rango -> error léxico.
              Por regla de lexema más largo, ".9" es CTE_FLOAT y "." solo es PUNTO.
  STRING    = \"({ESPACIO_BLANCO}|{SIGNOS}|{OPERADORES}|{LETRA}|{DIGITO}|\.|\!|\¡)*\"
              Validar en la acción: máximo 30 caracteres SIN contar las comillas. Más de 30 -> error
              léxico.
              Una comilla de apertura sin cierre válido -> error "string sin cerrar" (regla aparte
              para \" no seguida de un STRING válido).

Elementos que NO generan token ni salida: ESPACIO_BLANCO y comentarios.

COMENTARIOS:
  Apertura "//*"  Cierre "*//"  Anidamiento permitido de UN solo nivel.
  El TP REGEX los describe con el operador upto (~"*//"), pero ese operador corta en el PRIMER
  "*//" y rompe el anidamiento. Implementar con estado léxico (%state COMENTARIO) y contador:
    - "//*" en YYINITIAL     -> profundidad = 1, yybegin(COMENTARIO)
    - "//*" en COMENTARIO    -> profundidad++; si profundidad > 2 -> error "anidamiento de
                                comentarios mayor a un nivel"
    - "*//" en COMENTARIO    -> profundidad--; si llega a 0 -> yybegin(YYINITIAL)
    - cualquier otro carácter (incluido salto de línea) en COMENTARIO -> ignorar
    - EOF dentro de COMENTARIO -> error "comentario no cerrado" (usar <<EOF>>)
  Ejemplo válido:
    //*
    IF (a <= 30) THEN
      b ::= "correcto" //* asignación string *//
    ENDIF
    *//

ERRORES LÉXICOS (todos con línea y columna, base 1: yyline+1, yycolumn+1):
  - Carácter no reconocido (regla final con [^] en YYINITIAL).
  - CTE_INT fuera de rango.
  - CTE_FLOAT fuera de rango.
  - STRING de más de 30 caracteres.
  - STRING sin cerrar o con caracteres fuera del conjunto permitido.
  - Comentario sin cerrar.
  - Anidamiento de comentarios mayor a un nivel.
  El lexer NO debe abortar en el primer error: reporta y continúa.

TEMA ESPECIAL DEL GRUPO 3: POSITION
=====================================================================
La sentencia permite encontrar en qué posición de una lista de constantes enteras positivas se
encuentra un elemento pivot. El pivot deberá ser mayor o igual a uno. Si el pivot está varias
veces en la lista, el resultado es la primera posición en la que aparece. Si no se encuentra se
emite "Elemento no encontrado". La lista puede ser vacía, en cuyo caso se emite "La lista está
vacía". En ambos casos se asigna 0 al id.

Formato:
  id ::= POSITION(constante_entera; [lista de constantes])

Ejemplos (deben estar en prueba.txt):
  resul ::= POSITION(4;[10,20,30,40,5,4])   //* posición 6 *//
  resul ::= POSITION(5;[2,2,2,4])           //* no encontrado -> 0 *//
  resul ::= POSITION(1;[2,1,1,4])           //* posición 2 *//
  resul ::= POSITION(1;[])                  //* lista vacía -> 0 *//

Secuencia de tokens esperada para el primero:
  ID ASIGNACION POSITION PAR_A CTE_INT PUNTO_Y_COMA COR_A CTE_INT COMA CTE_INT COMA CTE_INT COMA
  CTE_INT COMA CTE_INT COMA CTE_INT COR_C PAR_C

En esta entrega solo se requiere reconocer los tokens. La semántica (búsqueda, mensajes, pivot >= 1)
corresponde a entregas posteriores.
